# EventFlow

Рабочий блокнот event-менеджера: мероприятия, единые задачи, календарь и Флуд.
Приложение работает в браузере и сохраняет данные между устройствами через
GitHub API. По решению владельца текущий JSON в репозитории остаётся публичным.

## Запуск

```bash
npm install
npm run dev
```

Production-сборка и тесты:

```bash
npm run build
npm test
```

## Рабочие разделы

- «Сегодня»: Горит, Просрочено, Сегодня, Жду ответа, Ближайшие 7 дней,
  задачи без срока и завершённые; важность, дата и статус редактируются в списке.
- Календарь: месяц, неделя, расписание; мероприятия, сроки и напоминания;
  многодневные события и выбор часового пояса.
- Карточка мероприятия: паспорт, стадии, общий чек-лист, услуги, ожидания,
  следующий шаг, рабочая история и закрепление.
- Флуд: единые входящие, доступ из меню, «Сегодня» и карточки; автосохранение,
  поиск, привязка к мероприятию, копирование, корзина, восстановление,
  ручное создание задачи из выделенного текста с подтверждением.
- Пользовательские метки и сохранённые фильтры.
- Шаблоны сообщений, настройки и полный JSON backup.

Старые страницы CRM остаются в исходниках для совместимости; активные маршруты
перечислены в `src/App.tsx`. Вложения файлов, AI-разбор Флуда и фоновые push-уведомления
не входят в текущую версию.

## Локальные данные

Компоненты не обращаются к `localStorage` напрямую. Все чтение, запись, миграция и backup проходят через `src/services/storage.ts`. Ключи используют namespace `eventflow.*`; текущая версия схемы хранится в `eventflow.schemaVersion`.

При первом запуске читается актуальная онлайн-копия. При изменении схемы сначала
сохраняется отдельная локальная резервная копия. Экспорт находится в «Настройки и
данные → Резервные копии». Он включает Флуд и настройки, но не GitHub token.

## Архитектура новых функций

[Инструкция для пользователя со скриншотами](https://lesauteur.github.io/EventFlow/guide/)
доступна также из меню приложения. Для обновления иллюстраций запустите
браузерный сценарий с `EVENTFLOW_GUIDE_SHOTS=1` и затем `scripts/build-guide.py`,
передав каталог скриншотов через `--screenshots`. Сценарий использует учебные данные.

- [Единый реестр и миграция](docs/TASK_REGISTRY.md).
- [Хранение и дальнейшие варианты защиты](docs/DATA_STORAGE.md).
- [План развития](docs/ROADMAP.md).

Браузерные проверки используют только искусственные данные и перехватывают
GitHub API; рабочий JSON не изменяется:

```bash
npx playwright install chromium
npm run build
# Запустить npm run dev в другом терминале, затем:
npm run test:browser
```

В CI сценарий сам запускает preview через `EVENTFLOW_QA_START=1`.

## Архитектура

- `src/config` — presets чек-листов и правила рисков.
- `src/data` — первоначальные demo data и навигация.
- `src/services` — storage, бюджет, Dashboard и template engine.
- `src/hooks` — единый слой состояния и toast.
- `src/components` — App Shell и повторно используемые элементы.
- `src/pages` — рабочие маршруты приложения.
- `src/types` — доменные TypeScript-типы.
- `tests` — тесты ключевой бизнес-логики.

Из-за требования полностью офлайн-сборки маршрутизация использует небольшой локальный совместимый адаптер с API `react-router-dom` для нужного приложению набора (`BrowserRouter`, `Routes`, `Route`, `Link`, `NavLink`, `useNavigate`, `useParams`, `useLocation`). Его можно заменить официальным пакетом без изменения страниц, когда установка пакетов из сети будет разрешена.
