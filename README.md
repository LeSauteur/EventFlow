# EventFlow

Локальный операционный помощник для event-менеджера. Приложение работает полностью в браузере, не использует backend, аккаунты, облако, API или внешнюю базу данных.

## Запуск

```bash
npm install
npm run dev
```

Production-сборка и тесты:

```bash
npm run build
npm test
```

## Рабочие разделы

- «Сегодня» с живыми KPI и задачами, сгруппированными по мероприятиям; задача выполняется прямо в списке.
- Упрощённая навигация: Сегодня, Мероприятия, Шаблоны, Настройки и быстрый список активных событий.
- Карточка `/events/:id` по умолчанию открывает единую рабочую ленту. Задачи, бюджет, документы и «Подробнее» доступны вкладками второго уровня.
- Быстрая запись создаёт задачу, заметку, расход, контакт, metadata документа или запись об отправленном сообщении.
- Детерминированный smart capture (без AI) распознаёт сумму и задачу со сроком, но применяет каждое действие только после подтверждения пользователя.
- Динамический чек-лист, открытые вопросы, правила рисков и бюджетный расчёт сохранены в структурированном разделе «Подробнее».
- Контрагенты и полный бюджетный калькулятор сохранены как контекстные deeper views.
- Шаблоны сообщений: переменные, редактирование, копирование, сохранение собственных версий и детерминированная проверка покрытия.
- Настройки и резервные копии: экспорт/импорт JSON и восстановление demo data.
- Глобальный поиск по мероприятиям, клиентам, городам и контрагентам.

Вкладка «Документы» хранит локальные metadata-записи. Фактическая загрузка файлов и внешние интеграции намеренно не добавлялись.

## Локальные данные

Компоненты не обращаются к `localStorage` напрямую. Все чтение, запись, миграция и backup проходят через `src/services/storage.ts`. Ключи используют namespace `eventflow.*`; текущая версия схемы хранится в `eventflow.schemaVersion`.

При первом запуске загружаются demo data. Экспорт резервной копии находится в «Настройки → Данные».

## Архитектура

- `src/config` — presets чек-листов и правила рисков.
- `src/data` — первоначальные demo data и навигация.
- `src/services` — storage, бюджет, Dashboard и template engine.
- `src/hooks` — единый слой состояния и toast.
- `src/components` — App Shell и повторно используемые элементы.
- `src/pages` — рабочие маршруты приложения.
- `src/types` — доменные TypeScript-типы.
- `tests` — тесты ключевой бизнес-логики.

Из-за требования полностью офлайн-сборки маршрутизация использует небольшой локальный совместимый адаптер с API `react-router-dom` для нужного приложению набора (`BrowserRouter`, `Routes`, `Route`, `Link`, `NavLink`, `useNavigate`, `useParams`, `useLocation`). Его можно заменить официальным пакетом без изменения страниц, когда установка пакетов из сети будет разрешена.
