# Хранение данных и следующий этап

По решению владельца текущие рабочие данные и Флуд используют прежнюю публичную
синхронизацию GitHub. Содержимое публичного JSON доступно без входа; интерфейс
пароля сам по себе этого не изменит. В этом PR не меняется видимость репозитория,
не переносятся рабочие записи и не меняется файл `data/eventflow-data.json`.
Разработка и браузерные проверки используют только искусственные записи.

До изменения схемы сохранена локальная копия JSON и Git bundle вне репозитория:
`C:/Users/domia/.codex/backups/EventFlow/2026-11-20-task-registry`.
При первом запуске новой версии создаётся отдельная резервная копия browser
storage до миграции. Она не синхронизируется и не попадает в коммит.

Простое дальнейшее решение без смены публичного хостинга: шифровать содержимое
рабочих коллекций в браузере (AES-GCM, ключ из пароля PBKDF2 с отдельной солью),
а в текущем GitHub хранить только шифротекст. Пароль вводится на каждом устройстве;
нужны восстановление из зашифрованной резервной копии, смена ключа и проверка
конфликтов до перехода. Другая возможность — сервер с персональным входом.
Переход требует отдельного согласования, не выполняется этим PR.

Шифрование будущих записей не скрывает уже опубликованную историю Git.
Очистка старой истории и отзыв прежних токенов — отдельные явные действия.
