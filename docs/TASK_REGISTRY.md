# Единый реестр задач, схема 7

Обновление 24.11.2026: реестр остаётся внутренним слоем календаря и совместимости.
Главная больше не разворачивает все пункты; основной интерфейс описан в
[концепции рабочего блокнота](NOTEBOOK_WORKFLOW.md).

Реестр — вычисляемое представление, а не третья копия задач. Источники:
`Event.commonChecklist`, `services[].checklist`, `waitingItems`, `nextStep`,
старые `checklistItems`, `questions`, `tasks`. Быстрая задача создаётся в
`checklistItems`; запись истории или Флуда сама по себе задачей не становится.

Ключ составлен из вида источника, eventId, serviceId и исходного id.
Переименование и перенос срока не меняют ключ. Совпадающий текст НЕ является
основанием для удаления или объединения записей. Явный `sourceKey` позволяет
читать старые алиасы без второй карточки. Действия во всех представлениях
записываются обратно в исходный объект. История не используется для повторного
создания уже существующих задач.

Три независимых признака: `priority`, вычисляемая по `deadline` срочность,
`manualHot` (работает и без даты). Напоминание `reminderAt` отдельно от срока.
Ожидания содержат `waitingFor`, `waitingSince`. Завершённые и отменённые задачи
не считаются просроченными; невыполненные не архивируются автоматически.

Даты без времени — календарные даты, до конца дня указанного пояса. Точные
сроки и напоминания — ISO с UTC/offset; редактирование с переводом из выбранного
IANA-пояса. Пояс по умолчанию Europe/Moscow, календарь допускает другой пояс.
Многодневное мероприятие включает обе даты паспорта. Дата мероприятия не
присваивается автоматически всем его задачам. Задачи без даты остаются видны
в реестре и отдельном списке календаря.

Схема 7 сначала сохраняет исходные ключи в `eventflow.backup.before-schema-7`,
затем дополняет существующие данные. Не очищает коллекции и не создаёт
tombstones для существующих записей. Если резервная запись не удалась,
миграция прекращается. Полный экспорт включает Флуд, метки и сохранённые фильтры.
Токен и технические sync-данные в экспорт не входят.

Синхронизация сохраняет текущий GitHub transport и версионирование записей.
Новые поля задач остаются внутри исходной записи; Флуд — отдельная коллекция.
Независимые вложенные задачи объединяются по их id и собственному updatedAt;
записи истории также объединяются по id. Удалённые услуги отмечаются tombstones
внутри мероприятия, чтобы не восстановить их старой копией. При одновременной
правке одного и того же поля, задачи или текста Флуда выигрывает более новая
версия. Действия над разными мероприятиями и записями Флуда объединяются по id.

Фильтры и выбранный часовой пояс — настройки устройства с экспортом/импортом;
задачи, закрепление мероприятий и Флуд синхронизируются. Старый клиент не знает
новую коллекцию: до объединения PR обе версии не использовать параллельно для
изменения рабочих данных.
